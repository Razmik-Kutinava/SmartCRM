# /crit-audit — аудит критического (PII / голос / hot-path)

Цель: аудит **сходится** — повтор на том же коммите без новых `open`.  
Критерии **K1–K5** — ниже. Журнал — `docs/operations/session/CRITICAL_LEDGER.md`.  
В `/review` на hot-path/PII/голосе — шаг 2; вручную — «проверь на критические».

## K1–K5 (SmartCRM)

| K | Смысл |
|---|--------|
| **K1** | Несанкционированный доступ / обход прав (API, Bitrix, чужой лид) |
| **K2** | Утечка PII (телефоны, email, ИНН, переписка) в логи, ответ API, UI чужому, промпт-утечка |
| **K3** | Голос/Hermes: silent open чужого лида, опасная мутация CRM без подтверждения, инъекция в интент |
| **K4** | Секреты в логах/коммите/ответе агента; raw SQL от LLM |
| **K5** | Разрушение данных: массовое затирание полей, DROP/TRUNCATE без go, необратимый merge |

## Правила

1. **Только K1–K5.** Стиль/UX — в «Не критично», на вердикт не влияют.
2. **Нет падающего теста — нет находки.** Нужны: `файл:строка`, сценарий, падающий тест. За 2 попытки нет — `rejected: no-repro`.
3. Находка → тест навсегда (RED `test: CA-NNN … [RED]` → fix GREEN).
4. Журнал — источник правды; не повторять `fixed`/`rejected`/`accepted-risk` без нового диффа на тех же строках.
5. Scope: `git diff <last_audited_sha>..HEAD` по затронутым путям (voice/hermes/leads/agents/api). Полный аудит — только по просьбе, одна зона за проход.
6. Сбой внешнего провайдера (Checko/Brave/Bitrix) — не наш баг без доказательства в коде.

## Сделай

1. Шапка + таблица CRITICAL_LEDGER → scope.
2. Дифф пустой → гейты зоны / check_step → `CLEAN`.
3. Кандидаты: свой проход + bugbot/security если владелец просил.
4. Вердикт: **CLEAN** (нет `open`) | **BLOCKED: N**.
5. Обновить ledger + `last_audited_sha` = HEAD. Коммит `docs: crit-audit …` (если вне `/review`).
