# Черновик правила: синхронизация backend README

> **Статус:** черновик — не в правилах до явного `go` от пользователя.  
> После апрува: влить в `.cursor/rules/smartcrm-repo-layout.mdc` (§ Backend README).

---

## Backend README Sync (обязательно при изменениях в `backend/`)

### Где живут README

| Уровень | Файл |
|---------|------|
| Весь бэкенд | `backend/README.md` |
| Зона | `backend/{api,core,agents,leadgen,rag,db,services,voice,integrations,email_sync,scripts,tests,data}/README.md` |
| Роуты | `backend/api/routes/README.md` (секции leads/, ops/, tenders/) |

Подпапки (`core/hermes/`, `leadgen/pipeline/` и т.д.) **не получают отдельный README** — только секция в README родителя.

### Когда обновлять (в том же PR/коммите, что и код)

| Изменение в коде | Обновить README |
|------------------|-----------------|
| Новый файл в существующей папке | Таблица «Файл → за что» в README этой зоны |
| Новая папка с 2+ файлами или пакет | Строка в `backend/README.md` + секция в README родителя |
| Переименование / удаление файла | Убрать или поправить строку в README зоны |
| Новый HTTP-роут | `api/routes/README.md` |
| Новый внешний сервис | `services/README.md` + при необходимости `leadgen/README.md` |
| Новая модель БД | `db/README.md` § models |
| Новый pytest-файл | `tests/README.md` |
| Новый CLI-скрипт | `scripts/README.md` |

### Формат записи

- Язык: **русский**, простые слова, 1 строка на файл.
- Без дублирования PRD — только «что лежит где», не бизнес-требования.
- Максимум ~2 экрана на README зоны; детали API → `docs/api/`.

### Чеклист агента (конец шага с кодом в `backend/`)

1. Затронутые зоны есть в таблице выше?
2. README родителя обновлён (или явно «без изменений README»)?
3. `backend/README.md` — карта актуальна, если появилась новая верхнеуровневая папка?

### Исключения

- Однострочный фикс без смены ответственности файла — README не трогать.
- `data/*.json` runtime — не описывать каждый файл, только тип в `data/README.md`.
