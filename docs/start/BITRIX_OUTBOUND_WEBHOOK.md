# Исходящий вебхук Битрикс24 + туннель (ngrok)

**Когда делать:** после первичного импорта лидов. На **localhost** без туннеля исходящий вебхук **не работает** — Битрикс в облаке не достучится до `127.0.0.1`.

**Без этого шага** SmartCRM уже синхронизирует новые лиды **опросом** (`BITRIX_AUTO_SYNC_MINUTES`, по умолчанию 5 мин). Исходящий вебхук нужен для **мгновенной** реакции (секунды).

Связанные доки: [`docs/modules/bitrix.md`](../modules/bitrix.md) § автосинк · входящий вебхук — там же.

---

## Что к чему

| Направление | Кто кого вызывает | Где настраивается |
|-------------|-------------------|-------------------|
| **Входящий** вебхук | SmartCRM → REST Битрикса | Битрикс + `BITRIX24_WEBHOOK_URL` в `.env` |
| **Исходящий** вебхук | Битрикс → SmartCRM | Битрикс + туннель на бэкенд `:8000` |
| **Опрос** | SmartCRM → Битрикс по расписанию | `BITRIX_AUTO_SYNC_MINUTES` в `.env` |

Эндпоинт SmartCRM для исходящих событий: **`POST /api/webhooks/bitrix/events`**

Код: `backend/api/routes/webhooks_bitrix.py`

---

## Шаг 1 — бэкенд запущен

```powershell
cd backend
uvicorn main:app --reload --port 8000
```

Проверка локально: `http://127.0.0.1:8000/docs` открывается.

---

## Шаг 2 — туннель на порт 8000

### Вариант A: ngrok

1. Установить [ngrok](https://ngrok.com/) (один раз).
2. В **отдельном** терминале:

```powershell
ngrok http 8000
```

3. В выводе ngrok найти строку **Forwarding**, например:

```
Forwarding   https://a1b2c3d4.ngrok-free.app -> http://localhost:8000
```

4. Скопировать **только** `https://a1b2c3d4.ngrok-free.app` — это **публичный URL бэкенда** на время сессии ngrok.

> URL меняется при каждом новом запуске ngrok (на бесплатном плане). После перезапуска ngrok — обновить URL в настройках исходящего вебхука в Битриксе.

### Вариант B: cloudflared

```powershell
cloudflared tunnel --url http://127.0.0.1:8000
```

В выводе будет `https://....trycloudflare.com` — использовать так же, как ngrok-URL выше.

## Шаг 3 — токен в `.env`

В корне репо `SmartCRM/.env` (не только `backend/.env`):

```env
BITRIX_OUTBOUND_TOKEN=придумай-длинный-секрет
```

Тот же секрет — в URL вебхука в Битриксе (шаг 4). Если переменная **пустая**, проверка токена на бэкенде отключена (для dev не рекомендуется на проде).

Перезапустить uvicorn после правки `.env`.

---

## Шаг 4 — исходящий вебхук в Битрикс24

**Битрикс24** → **Разработчикам** → **Другое** → **Исходящий вебхук**

| Поле | Что вставить |
|------|----------------|
| **URL обработчика** | `https://<URL-из-ngrok>/api/webhooks/bitrix/events?token=<BITRIX_OUTBOUND_TOKEN>` |
| **Токен приложения** | тот же секрет, что в `BITRIX_OUTBOUND_TOKEN` (можно дублировать; SmartCRM сверяет `?token=` или `auth.application_token`) |
| **События** | `ONCRMLEADADD`, `ONCRMLEADUPDATE` |

**Пример** (подставь свои значения):

```
https://a1b2c3d4.ngrok-free.app/api/webhooks/bitrix/events?token=zx0gps22qjyvhfrjvpdsya5yb758ires
```

Сохранить вебхук в портале.

---

## Шаг 5 — проверка

1. **Статус синка в SmartCRM:**

```bash
curl -s http://127.0.0.1:8000/api/leads/bitrix-sync-status
```

Ожидание: `webhook_configured: true`, `outbound_token_configured: true` (если токен задан).

2. **Создать или изменить тестовый лид** в Битрикс24.

3. Через несколько секунд лид должен появиться/обновиться в SmartCRM **без ожидания** цикла опроса.

4. Состояние последнего события/опроса: `backend/data/bitrix_sync_state.json` (runtime, не коммитить).

5. Логи uvicorn — запрос `POST /api/webhooks/bitrix/events` без 401/403.

## Частые проблемы

| Симптом | Причина | Что сделать |
|---------|---------|-------------|
| B24 не шлёт события | ngrok не запущен или URL устарел | Перезапустить туннель, обновить URL в Битриксе |
| 401/403 на `/events` | Неверный `token` | Сверить `?token=` в URL и `BITRIX_OUTBOUND_TOKEN` |
| Лид не появился | Только UI не обновился | Обновить список; проверить `bitrix_sync_state.json` |
| На prod с постоянным доменом | Туннель не нужен | URL: `https://<ваш-домен>/api/webhooks/bitrix/events?token=...` |
