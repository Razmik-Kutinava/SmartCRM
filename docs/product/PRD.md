## Идея проекта

SmartCRM — автономная система замены отдела продаж. Один оператор управляет 5 специализированными AI-агентами через **сквозной голосовой интерфейс**: любой модуль системы доступен голосом, не только лиды.

**Цель:** Один оператор = полноценный отдел продаж.

---

## Проблема

Отдел продаж — дорого, медленно, человеческий фактор. Рутина (поиск лидов, анализ, письма, отчёты) занимает 80% времени. AI может делать это быстрее и 24/7, если голос, почта, поиск и агенты работают как единая платформа.

---

## Решение

Мультиагентная CRM с:

- **Voice Layer** — Whisper → Hermes (модуль + интент) → LangGraph → действие + UI-реакция
- **5 агентов** уровня PhD; **Стратег** координирует сложные задачи (fanout)
- **Email-агент** — входящие, черновики, отправка по апруву
- **Поиск** Brave / Tavily / Serper → **RAG**, пополняемый автоматически
- **Groq** (основной) + **Ollama / Qwen** локально (fallback; см. `docs/stack/LLM.md`)

## Voice Layer — сквозной голосовой интерфейс

Голос — **основной** интерфейс (кнопки вспомогательные). Управление всей системой, не только лидами.

### Архитектура

```
Whisper (STT) → Hermes (интент + модуль) → LangGraph (агент/инструмент) → Действие
                                          ↓
                                     UI-реакция:
                                     - модалка с ответом
                                     - навигация на страницу
                                     - подсветка / фильтр данных
                                     - подтверждение перед отправкой
```

### Интенты по модулям

| Модуль | Примеры команд |
|--------|----------------|
| Лиды | «Пересчитай скор у Нерудной», «Создай задачу позвонить завтра», «Покажи аналитику по лиду» |
| Email | «Подготовь ответ на письмо от Hochland», «Отправляй», «Рассылка по квалифицированным» |
| Поиск | «Найди контакты директора X», «Обогати лид — сайт и телефон» |
| Аналитика | «Воронка за май», «Средний цикл сделки в квартале» |
| Агенты | «Маркетолог, письмо для Нерудной», «Аналитик, отчёт по воронке» |
| База знаний | «Загрузи PDF для тех. спеца», «Найди в базе про интеграции» |

### UI-реакции

- **Модалка** — письмо/анализ/ответ → оверлей «Отправить / Сохранить / Отклонить»
- **Навигация** — «Открой карточку Нерудной» → `/leads/{id}`
- **Подсветка** — «Просроченные задачи» → фильтр в списке
- **Апрув** — деструктивные и исходящие действия только после подтверждения (голос или кнопка)

**Фазы:** P1 лидов — Фаза 1; полный Voice Layer — Фаза 2; подтверждение и история — Фаза 3.

### Технические требования (дополнение)

- **Транспорт:** расширение существующего WebSocket `/ws/voice` (не отдельный Event Bus) — payload `voice_action` на фронт.
- **Hermes:** в JSON интента — `module`, `intent`, `slots`, флаг `ui_action` (`navigate` | `modal` | `filter` | `approve`).
- **Навигация:** `intent: navigate`, `target: "/leads/{id}"` | `"/leads/analytics"` → мгновенный `goto` в SvelteKit.
- **Модалки:** комплексный ответ агента (КП, анализ, тендер) — оверлей поверх текущего экрана, контекст не теряется.
- **Голосовой CRUD лидов (Фаза 1):** поля (бюджет, отрасль), стадия, задачи, комментарии, лог касаний — через существующие API; см. контракт в [`ARCHITECTURE.md`](ARCHITECTURE.md#контракт-voice_action).

## Email-агент

Подключённые рабочие ящики: чтение, анализ, черновик, отправка по команде.

| Функция | Описание | Фаза |
|---------|----------|------|
| Входящие + синк | IMAP, список в `/email`, фоновая синхронизация | 2 |
| Анализ | Тип: вопрос / апрув / жалоба / спам | 2 |
| Черновик | Маркетолог или Стратег → модалка на апрув | 2 |
| Отправка | «Отправляй» голосом или кнопка | 2 |
| Автоответ | FAQ по правилам из Ops | 3 |
| Рассылки | Сегмент лидов → текст → отправка | 3 |
| Цепочки касаний | Маркетолог ведёт 20 касаний | 3 |
| Автолинк | Домен компании → карточка лида | 3 |

**Стек:** IMAP/SMTP (OAuth или app password); credentials только в env; исполнитель — Маркетолог.

### Режимы работы

| Режим | Фаза | Поведение |
|-------|------|-----------|
| **Ассистирующий** | 2 | Черновик сложного B2B-письма → модалка → апрув → отправка (голос «отправляй» или кнопка) |
| **Автономный** | 3 | Автоответ FAQ по правилам из Ops; без апрува только для простых входящих |

**Голосовые рассылки (Фаза 2–3):** надиктовать идею → агент строит сегмент (например, стадия «Переговоры») + текст → апрув → отправка.

Подробно: `docs/email/`.

## Self-improvement — самообучение агентов

RAG и промпты улучшаются от использования системы.

### Цикл пополнения RAG

```
Поиск → результат → чанки Q/A → RAG агента
PDF/DOCX → чанкинг → RAG (агент или общий)
Диалог → факты о лиде/компании → RAG того же агента
URL вендора → краулинг → RAG тех. спеца
```

| Источник | Агент | Авто |
|----------|-------|------|
| Поиск по лиду | Аналитик / Маркетолог | Да, если релевантность > порога |
| PDF пользователя | Указанный | Да, после загрузки |
| Сайт вендора (конфиг) | Тех. спец | По расписанию / команде |
| Диалог | Тот же агент | Да, только факты о сделке |
| Книга EPUB/PDF | По выбору | По команде |

### Search-to-Q&A (Фаза 2)

Веб-результат поиска (Brave/Tavily/Serper) **не только в лог UI**: отдельный LLM-пайплайн превращает сниппеты в пары «вопрос–ответ» → Chroma с метаданными агента. Порог релевантности обязателен. Детали: [`docs/stack/RAG.md`](../stack/RAG.md#search-to-qa-фаза-2).

**RAG тех. спеца (`tec`):** приоритетный контур — PDF вендоров, спецификации; краулинг URL — Фаза 3. Без изолированного `tec` анализ ТЗ тендеров недостоверен.

### Промпты

- Редактирование в Ops → Агенты
- Версионирование (история) — **Фаза 2**
- A/B два промпта по трейсам Hermes — **Фаза 3**
- Авто-суфлёр Стратега по слабым ответам — **Фаза 3**

## Оркестрация агентов

Стратег — supervisor в LangGraph: fanout → сбор → синтез → UI.

| Сценарий | Агенты | Результат |
|----------|--------|-----------|
| Анализ + письмо | Аналитик ∥ Маркетолог | Модалка: анализ + черновик |
| Оценка тендера | Тех. спец ∥ Экономист → Стратег | Участвовать / нет |
| Еженедельный отчёт | Аналитик ∥ Экономист ∥ Маркетолог | Сводный дашборд |
| Похожие лиды | Аналитик ∥ Поиск ∥ Маркетолог | Список + рекомендация |

```
Стратег (supervisor)
├── Аналитик
├── Экономист
├── Маркетолог
└── Тех. спец
     → fanout → синтез → UI
```

**Фазы:** fanout + синтез — Фаза 2; трейс выбора и ручное назначение — Фаза 3.

### Поток оркестрации (техника)

1. Whisper → текст → Hermes (`module`, `intent`, `ui_action`).
2. Простая задача → один агент / API.
3. Комплексная («проверь лид и напиши письмо») → **Стратег**: fanout (например Аналитик ∥ Маркетолог; при тендере — Тех.спец ∥ Экономист **по необходимости**, не в каждом сценарии).
4. Стратег собирает **единый JSON-пакет** `voice_action` → WebSocket → UI (модалка + данные + черновик + кнопки).

Контракт JSON: [`ARCHITECTURE.md`](ARCHITECTURE.md#контракт-voice_action), реализация: [`docs/agents/langgraph.md`](../agents/langgraph.md#пакет-voice_action-стратег).

## Тендеры

**Реальность:** бесплатных API с стабильным качеством нет; парсеры ЕИС нестабильны.

| Этап | Что | Фаза PRD |
|------|-----|----------|
| Сейчас | ЕИС + TenderGuru (лимит) + Serper/Tavily | 1 |

## Принципы

1. **Голос — основной интерфейс** всех модулей; кнопки — вспомогательные
2. **Стратег координирует** сложные задачи; агенты работают параллельно где уместно
3. **Groq → Ollama fallback** — не зависим от одного провайдера
4. **RAG пополняется** от поиска, документов и диалогов
5. **Апрув** перед исходящими и деструктивными действиями
6. **Язык UI — русский**
7. **Приватность** — Ollama локально; Groq по политике (`docs/stack/LLM.md`, `docs/start/RUNBOOK.md`)

## Фича: балльная воронка лидов

Референс: «CRM — points system» (Rails). Детерминированная подсказка балла + операционный контур сделки в `/leads`.

### Суть

`scoreAdvisory` + суммы ₽ + задачи/комментарии/аудит; **балл в БД задаёт менеджер**; агенты дают совет, не перезаписывают `score` (дефолт).

### P1 — done-критерии

1. Конфиг `scoring_advisory`, флаги в `crm_settings.json`; `GET /api/crm/config`
2. `core/lead_score_advisory.py` → `suggestedScore`, `warnings`, `breakdown`; без записи в БД
3. `GET/PATCH /api/leads/{id}` → `scoreAdvisory`
4. Приоритет от `score` менеджера + `priority_thresholds`
5. `agents_may_update_score=false` по умолчанию

### P2 — done-критерии

1. Комментарии (`LeadComment`, API, UI карточки)
2. Аудит полей (`LeadFieldAudit`)
3. Валидация переходов стадий (`stage_transition_rules`)

### P3 — done-критерии

1. Расширенные SLA-протоколы (после стабильности P1–P2)
2. Экспорт/отчёты по баллам и воронке

### Не-скоуп

- Замена auth на Pundit-уровень
- Перенос Rails UI — только поведение на SvelteKit
- Автоимпорт истории из внешней CRM без запроса

### Метрики успеха

| Метрика | Измерение |
|---------|-----------|
| Стабильность подсказки | Валидный `scoreAdvisory` без 5xx, 7 дней |
| Прозрачность | Объяснимый балл в UI (P2+) |
| Время реакции | Приоритет в списке < 2 с после сохранения |
| Регрессии | Нулевой блокер CRUD `/leads` после P1 |

### Риски

| Риск | Митигация |
|------|-----------|
| Агенты перезаписывают `score` | `agents_may_update_score=false`, аудит |
| Расхождение сумм UI/API | Валидация PATCH, юнит-тесты |
| Этапы БД ≠ конфиг | Нормализация, предупреждение в Ops |
| Раздувание аудита | Лимит записей / отдельная таблица |

### Зависимости

- Миграции — Migration Gate + `go`
- Согласование: `docs/modules/leads.md`, `docs/agents/langgraph.md`
