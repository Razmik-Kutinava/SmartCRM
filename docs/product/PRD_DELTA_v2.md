## Voice Layer — сквозной голосовой интерфейс

### Суть

Голос — не просто ввод команд для лидов. Это единая платформа управления всей системой. Любой модуль, любое действие доступно голосом.

### Архитектура

```
Whisper (STT) → Hermes (интент + модуль) → LangGraph (агент/инструмент) → Действие
                                          ↓
                                     UI-реакция:
                                     - модалка с ответом
                                     - навигация на страницу
                                     - подсветка данных
                                     - подтверждение перед отправкой
```

### Интенты по модулям

| Модуль | Примеры голосовых команд |
|--------|--------------------------|
| Лиды | «Пересчитай скор у Нерудной компании», «Создай задачу позвонить завтра», «Покажи аналитику по лиду» |
| Email | «Подготовь ответ на последнее письмо от Hochland», «Отправляй», «Составь рассылку по квалифицированным лидам» |
| Поиск | «Найди контакты директора компании X», «Обогати лид — найди сайт и телефон» |
| Аналитика | «Покажи воронку за май», «Какой средний цикл сделки в этом квартале» |
| Агенты | «Маркетолог, напиши письмо для Нерудной», «Аналитик, сделай отчёт по воронке» |
| База знаний | «Загрузи этот PDF для тех. спеца», «Найди в базе что-нибудь про интеграции» |

### UI-реакции на голос

- **Модалка** — агент возвращает текст (письмо, анализ, ответ) → показать в оверлее с кнопками «Отправить / Сохранить / Отклонить»
- **Навигация** — «Открой карточку Нерудной» → роутер переходит на `/leads/{id}`
- **Подсветка** — «Покажи все просроченные задачи» → список с фильтром применяется автоматически
- **Апрув перед действием** — любое деструктивное или отправочное действие требует подтверждения голосом или кнопкой

### P1 Voice Layer

- [ ] Hermes распознаёт модуль + интент для всех разделов (не только лиды)
- [ ] UI получает событие `voice_action` и рендерит модалку с результатом агента
- [ ] Навигация по голосу через роутер SvelteKit

### P2 Voice Layer

- [ ] Голосовое подтверждение («да, отправляй» / «нет, отмени»)
- [ ] История голосовых команд в Ops → Voice

## Email-агент — автономная работа с почтой

### Суть

Подключённые рабочие ящики. Агент читает входящие, готовит ответы, отправляет по команде. Рассылки голосом или вручную.

### Возможности

| Функция | Описание |
|---------|----------|
| Входящие | Агент анализирует текст → определяет тип (вопрос, апрув, жалоба, спам) |
| Подготовка ответа | Маркетолог / Стратег готовит черновик → модалка на апрув |
| Отправка | Голосом «отправляй» или кнопкой в UI |
| Автоответ | Простые входящие (FAQ-уровень) → агент отвечает сам по правилу из конфига |
| Рассылки | Голосом или через UI: выбор сегмента лидов → сочинить текст → отправить |
| Привязка к лиду | Письмо от домена компании → автолинк к карточке лида |

### Стек

- IMAP/SMTP для подключения ящиков (OAuth или пароль приложения)
- Агент-маркетолог как основной исполнитель
- Шаблоны цепочек касаний (20 касаний из PRD Фаза 2)

### P1 Email-агент

- [ ] Подключение ящика (IMAP + SMTP), хранение credentials в env
- [ ] Список входящих в `/email`, синхронизация фоном
- [ ] Анализ письма агентом → тип + черновик ответа
- [ ] Апрув и отправка (голос или кнопка)

### P2 Email-агент

- [ ] Автоответ на простые входящие по правилам из Ops
- [ ] Рассылки по сегменту лидов
- [ ] Цепочки касаний (маркетолог ведёт автоматически)
- [ ] Автолинк письма → карточка лида

## Self-improvement агентов — постоянное самообучение

### Суть

Агенты не статичны. Каждый поисковый запрос, каждый загруженный документ, каждый диалог — потенциальный источник новых знаний. RAG пополняется автоматически.

### Цикл самообучения

```
Поисковый запрос → результат → чанки Q/A → RAG агента
PDF/DOCX загружен → смысловой чанкинг → RAG агента (или общий)
Диалог агента с лидом → ключевые факты → RAG агента
Внешний сайт (docs вендора) → краулинг → чанки → RAG тех. спеца
```

### Правила пополнения RAG

| Источник | Агент | Автоматически |
|----------|-------|---------------|
| Поисковый запрос по лиду | Аналитик / Маркетолог | Да, если релевантность > порога |
| PDF загружен пользователем | Указанный агент | Да, сразу после загрузки |
| Сайт вендора (URL в конфиге) | Тех. спец | По расписанию или по команде |
| Диалог агента | Тот же агент | Да, только факты о компании/лиде |
| Книга (EPUB/PDF) | Любой по выбору | По команде пользователя |

### Улучшение промптов

- В Ops → Агенты: редактирование системного промпта каждого агента
- Версионирование промптов (история изменений)
- A/B: два промпта → сравнение качества ответов в трейсах Hermes
- Авто-суфлёр: Стратег анализирует слабые ответы агентов и предлагает правки промпта

### P1 Self-improvement

- [ ] Поисковый результат → чанки → RAG конкретного агента (кнопка «Сохранить в базу» в `/search`)
- [ ] Версионирование промптов в Ops → Агенты

### P2 Self-improvement

- [ ] Краулинг URL вендора → RAG тех. спеца (по расписанию)
- [ ] Авто-суфлёр Стратега по слабым ответам
- [ ] A/B промптов в Ops

## Оркестрация агентов — Стратег как координатор

### Суть

При сложной задаче Стратег запускает несколько агентов параллельно, собирает результаты, синтезирует финальный ответ.

### Сценарии оркестрации

| Команда | Агенты | Результат |
|---------|--------|-----------|
| «Проанализируй лид и напиши письмо» | Аналитик (данные) + Маркетолог (письмо) параллельно | Анализ + черновик письма в одной модалке |
| «Оцени тендер» | Тех. спец (соответствие) + Экономист (НМЦ/маржа) + Стратег (решение участвовать) | Рекомендация с обоснованием |
| «Еженедельный отчёт» | Аналитик (воронка) + Экономист (финансы) + Маркетолог (касания) | Сводный дашборд |
| «Найди похожих лидов» | Аналитик (профиль) + Поиск (Brave/Tavily) + Маркетолог (стратегия захода) | Список с рекомендацией |

### Архитектура LangGraph

```
Стратег (supervisor node)
├── Аналитик (node)
├── Экономист (node)
├── Маркетолог (node)
└── Тех. спец (node)

Параллельный fanout → сбор результатов → Стратег синтезирует → UI
```

### P1 Оркестрация

- [ ] Стратег определяет какие агенты нужны для задачи
- [ ] Параллельный запуск 2+ агентов через LangGraph fanout
- [ ] Синтез результатов в один ответ

### P2 Оркестрация

- [ ] Стратег объясняет почему выбрал тех или иных агентов (трейс в Ops)
- [ ] Пользователь может вручную назначить агентов для задачи

## Тендеры — реалистичный roadmap

### Текущее состояние

Бесплатных API с нормальным качеством нет. Парсеры ЕИС работают нестабильно. Приоритет — настроить насколько возможно бесплатно, платный API подключить после первой закрытой через тендер сделки.

### Фазы

| Фаза | Что | Когда |
|------|-----|-------|
| Сейчас | Парсер ЕИС + TenderGuru бесплатный лимит + ручной поиск через Serper/Tavily | MVP |
| После первой продажи | Контур.Закупки API или аналог | При окупаемости |
| Зрелость | Полный мониторинг, авто-уведомления, агент-тендерный специалист | Фаза 3 |

### Агент-тендерный специалист (Фаза 3)

- Мониторит ключевые слова и ОКПД2 автономно
- Анализирует документацию тендера (Тех. спец + Экономист)
- Готовит решение «участвовать / нет» с обоснованием
- Ведёт календарь дедлайнов подачи заявок
