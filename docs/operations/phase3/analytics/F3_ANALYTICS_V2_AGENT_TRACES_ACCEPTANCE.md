# Аналитика v2 — эффективность агентов по трейсам (acceptance)

**PRD_MAP:** «Эффективность агентов по трейсам»

## Было

- `/ops/stats` — общие цифры (интенты, latency, 👍/👎 суммарно)
- Нет среза **по каждому агенту**
- Нет явных ссылок «куда идти улучшать»

## Стало

| Компонент | Изменение |
|-----------|-----------|
| `core/agent_trace_analytics.py` | метрики по агенту: вызовы, 👍/👎, ошибки, топ-интенты, `needsAttention` |
| `GET /api/ops/analytics/agents` | JSON для UI и мониторинга |
| `/ops/stats` | блок «Эффективность агентов» + ссылки на трейсы / A/B / промпты |
| `/ops/agents?agent=…` | переход с карточки «Улучшить» |

## Цикл улучшения

1. Оператор ставит 👎 на трейсе
2. `/ops/stats` показывает агента с низким % или без фидбека
3. «Улучшить» → промпт агента или `/ops/intents/improve` (A/B)

## Критерии

- [x] 5 агентов в отчёте
- [x] Учёт fanout + strategist на evaluate_tender
- [x] Флаг `needsAttention` при ≥40% 👎 или ошибках
- [x] pytest unit + API

## Не в scope

- Фидбек отдельно на каждого агента в одном трейсе (пока общий 👍/👎 на команду)
- Автозапуск суфлёра по `attention` — Ф4
