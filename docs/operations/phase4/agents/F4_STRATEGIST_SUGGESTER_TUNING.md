# Ф4 — Авто-суфлёр Стратега (тюнинг)

**Откуда:** Ф3 — базовый суфлёр на `/ops/agents` — см. [`F3_STRATEGIST_SUGGESTER_ACCEPTANCE.md`](../../phase3/agents/F3_STRATEGIST_SUGGESTER_ACCEPTANCE.md).

**Сейчас:** Стратег (Groq) анализирует 👎 Hermes, 👎 agent_run_log, gate-fail → предлагает `prompt_append` для **любого** агента + Hermes; apply только по апруву оператора.

**Зачем Ф4:** без override в рантайме правки не влияют на ответы; мало качественных сигналов и нет проверки «стало лучше».

**PRD_MAP:** Фаза 4 → Авто-суфлёр (тюнинг).

---

## Чеклист (после апрува Ф3)

| # | Задача | Что сделать | Проверка |
|---|--------|-------------|----------|
| 1 | **Runtime → override** | Агенты в бою читают `agent_prompt_{id}.txt` (как Ops) | После apply на `/ops/agents` ответ маркетолога/аналитика меняется |
| 2 | **👎 с эталоном** | При минусе — поле «какой ответ ожидали» / expected intent | Суфлёр и gate видят контекст, не только «плохо» |
| 3 | **Больше сигналов** | Лимиты ↑; опция «все 👎 за 7 дней»; агрегация по агенту/интенту | Отчёт суфлёра не пустой при реальной работе |
| 4 | **Apply → проверка** | После apply: авто-подсказка «прогони gate / A/B» для этого агента | Оператор не оставляет регрессию вслепую |
| 5 | **История суфлёра** | JSON в `data/artifacts/` + строка в Ops (что предложили, что применили, Δ gate) | Сравнение версий промпта во времени |
| 6 | **Периодический запуск** | Опция: N новых 👎 или cron → уведомление в очередь Ops (без автоприменения) | Не забывать про деградацию |
| 7 | **Цепочка Hermes** | improve: suggest-prompt → A/B → apply (один поток) | Меньше ручных шагов для голоса |
| 8 | **Per-agent UI** | Кнопка «суфлёр только для этого агента» на карточке агента | Точечный тюнинг без шума от других |

---

## Не в этом чеклисте

- Отдельная страница «лаборатория суфлёра» (если хватит блока на `/ops/agents`)
