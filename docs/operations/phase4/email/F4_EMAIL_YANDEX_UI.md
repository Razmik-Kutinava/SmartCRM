# Ф4 — UI почты в стиле Яндекс.Почты

**Референс:** рабочий ящик оператора (Yandex Mail).  
**Цель:** `/email` визуально и по навигации как Яндекс — без смены backend-контрактов на первом шаге.

**Код:**
- `frontend/src/components/email/EmailYandexSidebar.svelte`
- `frontend/src/components/email/EmailYandexSearchBar.svelte`
- `frontend/src/lib/email/emailListLogic.js`
- `frontend/src/routes/email/+page.svelte`

### Маппинг папок

| Папка UI | Логика |
|----------|--------|
| Входящие | не outbound/campaign/archive |
| Главное | `localStorage` starred thread ids |
| С вложениями | эвристика: вложен, .pdf, attachment… |
| Zoho | subject/snippet содержит zoho |
| Templates | subject/snippet: template/шаблон |
| рассылка | `category === campaign` |
| уведомления | from: noreply, notification, … |
| Архив | `isArchived` |
| Отправленные | `category === outbound` |
| Удалённые / Черновики / Спам | placeholder (Спам disabled) |

## Поиск и чипы фильтров

| Чип | Поведение |
|-----|-----------|
| Поиск + «Найти» | subject, snippet, previewFrom |
| С вложениями | toggle, та же эвристика |
| Дата | dateFrom / dateTo по `lastMessageAt` |
| Папки | доп. фильтр по ключу папки |
| От кого | substring в previewFrom |
| Кому | substring в recipients (если есть в треде) |
| Ещё | зарезервировано под непрочитанные (`is_read` в API — позже) |

## Хвост (не этот шаг)

| # | Нужно | Зачем |
|---|-------|-------|
| 1 | `is_read` + непрочитанные в API | чип «Ещё», счётчик непрочитанных |
| 2 | `has_attachments` из IMAP | точные вложения, не эвристика |
| 3 | IMAP-папки Trash/Drafts/Spam | синк с сервером |
| 4 | Метки (как «Добавить метку» в Яндексе) | пользовательские теги |
| 5 | Светлая тема треда/compose | сейчас модалки могут остаться тёмными |
