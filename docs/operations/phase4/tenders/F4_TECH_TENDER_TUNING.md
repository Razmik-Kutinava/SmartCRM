# Ф4 — Тех. спец — тендеры (тюнинг и автоматизация)

**Откуда:** Ф3 закрыл базу (мониторинг, уведомления, бесплатные источники, вердикт участия).  
**Зачем Ф4:** убрать ручную «курьерскую» работу оператора и поднять качество тех. разбора.

---

## Критичные пробелы после Ф3

| # | Проблема | Что даёт |
|---|----------|----------|
| 1 | Мониторинг находит, дальше всё руками | Цепочка без кликов |
| 2 | ТЗ часто не в карточке — только краткое описание | Точная тех. оценка |
| 3 | JSON тех. спеца не виден как чеклист | Решение «идём / не идём» за минуты |
| 4 | Уведомление ≠ действие в CRM | Ничего не теряется по дедлайну |
| 5 | Нет eval/gate на тендерный разбор | Стабильный вердикт |

Контур.Закупки — отдельно: [`F4_KONTUR_GATE.md`](F4_KONTUR_GATE.md) (после первой сделки).

## План Ф4 (чеклист)

### Автопайплайн мониторинг → оценка

- [ ] Правило в `tender_monitor`: при новом матче с `relevance ≥ порога` — постановка в очередь оценки
- [ ] Фоновая задача: скачать доки → `document_text` → `POST /evaluate` (без UI)
- [ ] In-app + календарь: пуш с готовым `participation.verdict`, не «новый тендер — смотри сам»
- [ ] Оператор: вкл/выкл автооценку и порог релевантности в `/ops/tender-monitor`

### Автозагрузка документации

- [ ] Парсер ссылок на файлы из карточки Gosplan / zakupki (или через Контур после gate)
- [ ] Извлечение текста (существующий upload-пайплайн) → слот `document_text`
- [ ] Кэш скачанных PDF по `external_id` (не качать повторно)
- [ ] Fallback: если доков нет — явный флаг `has_document: false` в уведомлении

### Матрица «ТЗ ↔ продукты» (UI)

- [ ] Структурированный вывод тех. спеца: `requirements[]` — `{требование, статус: ok|gap|risk, продукт, комментарий}`
- [ ] Вкладка на `/tenders`: таблица соответствия + блокеры + вопросы заказчику
- [ ] Экспорт фрагмента в КП / заметку лида (связка с лидом из тендера)

### Мониторинг → действие в CRM

- [ ] При `participate` / `caution`: черновик задачи или лид + дедлайн из тендера
- [ ] При `no`: архив / «отклонён» с кратким rationale в snapshot
- [ ] Напоминание за N дней до `deadline`, если вердикт «участвовать» и нет лида

### Качество (eval / gate)

- [ ] 15–20 эталонных кейсов: ТЗ + ожидаемый вердикт / ключевые gap
- [ ] Скрипт `run_eval_tender_tech.py` — pass rate, регрессия при смене промпта/RAG
- [ ] Порог gate в Ops (как Hermes KPI) — не деплоить промпт ниже baseline

### Контур (после gate)

- [ ] См. [`F4_KONTUR_GATE.md`](F4_KONTUR_GATE.md) — доки из API закрывают п. «автозагрузка» для платных карточек

## Критерии готовности Ф4 (acceptance)

- [ ] Новый тендер из мониторинга → вердикт в уведомлении без ручной загрузки (где есть доки)
- [ ] UI: матрица ТЗ ↔ продукты на сохранённом тендере
- [ ] Eval тендерного тех. разбора ≥ согласованного порога
- [ ] Smoke: monitor → queue → evaluate → save → optional lead
