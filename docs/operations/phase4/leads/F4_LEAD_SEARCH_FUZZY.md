# Ф4 — Нечёткий поиск лидов по названию

## Цель

Строковый и голосовой поиск в `/leads/list`: если точного/substring-совпадения нет (STT-опечатка, похожее звучание) — показать **топ-3–5** ближайших компаний по названию, а не пустой список.

## Scope

| Делаем | Не делаем |
|--------|-----------|
| Нечёткий матч **названия компании** в фильтре списка | Обучение / запоминание «одобренных» ошибок |
| Топ **5** кандидатов (не меньше 3 при наличии) | Молчаливый `open_lead` чужого лида по слабому fuzzy |
| Подсветка первого при **сильной** похожести | Весь Voice Layer, Whisper, Hermes parse, CRUD |
| Тот же путь для голоса (`list_leads` → `search`) и ручного ввода | Fuzzy по телефону/email/городу (остаётся includes) |

## Поведение

1. Пустой `search` → без изменений (все лиды + прочие фильтры).
2. Есть substring-матч (как сейчас: company/contact/… содержит запрос) → только эти строки, порядок сортировки списка как сейчас.
3. Substring пуст → ранжировать **все** лиды по похожести `company` ↔ запрос, взять топ-5; слабый скор **не** обнуляет выдачу.
4. Один очень близкий (высокий score) — первый в списке; UI может пометить «похоже», без авто-открытия карточки.
5. `open_lead` / «открой её» — **не** расширять silent-open на слабый fuzzy (память last — только из явного списка матчей после поиска).

## Алгоритм (MVP)

- Нормализация: lower, `ё→е`, схлопнуть пробелы; сравнение и «с пробелами», и «без пробелов».
- Скор: `difflib`-подобный ratio / Левенштейн на нормализованных строках (+ бонус за общий префикс / token overlap).
- Грубая «фонетика» без словаря: близкие замены букв учитываются через edit-distance («втф банг» ≈ «втб банк»).
- Константа `FUZZY_TOP_N = 5`. Без хранения пользовательских алиасов.
